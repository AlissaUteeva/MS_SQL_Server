## Задача 1 Создание кластеризованного индекса на heap-таблице
Условие: Дана таблица dbo.Products с 100 000 строк без каких-либо индексов (heap). Столбцы: ProductID INT, Name NVARCHAR(100), Price DECIMAL(10,2), CategoryID INT.

Требуется:

1. Создайте кластеризованный индекс на ProductID.
2. Выполните запрос SELECT * FROM dbo.Products WHERE ProductID = 50000;
3. Сравните план выполнения до и после создания индекса.
4. Зафиксируйте количество logical reads в обоих случаях.

Ожидаемый результат: Table Scan → Clustered Index Seek; снижение logical reads в 10+ раз.

## Задача 2 Некластеризованный индекс для точечного поиска
Условие: Та же таблица dbo.Products, кластеризованный индекс на ProductID уже создан.

Требуется:

1. Создайте некластеризованный индекс на Name.
2. Выполните SELECT ProductID, Name, Price FROM dbo.Products WHERE Name = N'Товар-777';
3. Определите, используется ли Key Lookup. Объясните, почему.

Ожидаемый результат: Index Seek + Key Lookup (так как Price не входит в индекс).

## Задача 3 Разница между Seek и Scan
Условие: Таблица dbo.Orders с 500 000 строк, кластеризованный индекс на OrderID, некластеризованный на CustomerID.

Требуется: Выполните три запроса и определите тип операции в плане:

1. WHERE OrderID = 100;
2. WHERE OrderID > 100 AND OrderID < 200;
3. WHERE OrderID > 0; (возвращает все строки)

Ожидаемый результат: Seek → Seek (Range) → Clustered Index Scan. Объясните, почему SQL Server выбирает разные операторы.

## Задача 4 Влияние selectivity на выбор индекса
Условие: Таблица dbo.Users с 200 000 строк. Столбец Gender содержит только 2 значения (M/F), столбец Email уникален.

Требуется:

1. Создайте некластеризованные индексы на Gender и Email.
2. Выполните SELECT * FROM dbo.Users WHERE Gender = 'M'; и SELECT * FROM dbo.Users WHERE Email = 'user@test.com';
3. Проанализируйте, какой индекс используется в каждом случае и почему.

Ожидаемый результат: Для Gender — вероятно, Clustered Index Scan (индекс игнорируется из-за низкой селективности); для Email — Index Seek.

## Задача 5 Удаление и пересоздание индекса
Условие: В таблице dbo.Customers есть некластеризованный индекс NCIX_Email на столбце Email.

Требуется:

1. Удалите индекс через DROP INDEX.
2. Проверьте, что индекс исчез, через sys.indexes.
3. Пересоздайте индекс, добавив в него столбец LastName как ключевой.
4. Сравните размер индекса до и после через sys.dm_db_index_physical_stats.

Ожидаемый результат: Понимание влияния количества ключевых столбцов на размер индекса.
